3.

Type a URL, hit enter — the browser fires a request across the internet to whichever server owns that address. The server digs up the matching page and sends the files back: HTML, CSS, JS, images. The browser parses all of it and paints it on your screen.

Examplle: type www.google.com and the whole round trip — request out, files back, page rendered — happens in under a second.

5.) Web servers

It is a Software or a computer that stores your site and serves it up on request. Commonly used web servers are: Apache, Nginx and LiteSpeed.
Example: opening google.com means a server somewhere just processed your request and handed the page back.

6.) Frontend developer, backend developer, DBA — roles

a.Frontend builds the part where users click on — HTML/CSS/JS, layout, making sure it doesn't break on mobile. 

b.Backend is the part which nobody sees: server logic, APIs, request handling, usually in Java, Python, PHP, or Node.
 
c.The DBA sits inside both(frontend and backend) of them, designing and securing the database so the other two actually have data to work with.

Take a shopping site: frontend is the storefront, backend handles login and checkout, the DBA makes sure none of the order data gets lost.

7.) Setting up VS Code for HTML/CSS/JS

8.) Static vs. dynamic websites

Static -> same page for every visitor, no database, only changes when someone edits the files by hand. Portfolios, brochure sites.

Dynamic -> content shifts per user or per query against a database — Facebook, Amazon, Instagram. Heavier to build, but does a lot more.

9.) Browsers and their rendering engines

Chrome, Edge, and Opera all sit on Blink — fast, current with web standards. Firefox runs its own engine, Gecko, with more emphasis on standards and privacy. Safari uses WebKit, built specifically around Apple hardware and battery efficiency.
